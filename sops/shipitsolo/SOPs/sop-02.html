Block 00 — Before you start 02

How to prompt an AI coding assistant effectively

The quality of what you build is directly proportional to the quality of what you ask for. This SOP closes that gap.

When an AI coding assistant produces something wrong, most people blame the tool. Most of the time, the tool did exactly what it was asked to do. If your description is vague, the code will be vague.

The gap between a good prompt and a bad one is not technical knowledge. It is clarity. Anyone can learn this in an afternoon.

the four parts of a good prompt
  • The role
    Tell the AI what kind of expert to behave like. "You are a senior frontend developer" produces different results than no role at all.
  • The context
    What already exists? What stack are you using? Paste your PRD here. Every time.
  • The task
    One task per prompt. Not "build the whole app" but "build the contact form." Smaller tasks produce better results.
  • The constraint
    What it cannot do. No external libraries unless specified. No placeholder data. Constraints prevent the AI from making decisions you did not ask it to make.
bad prompt vs good prompt
Same task, two different prompts
Bad "Build a form that takes ingredients and shows a menu." Good "You are a senior frontend developer building a single-page web app. Here is the PRD: [paste PRD]. Build a text input where users type a comma-separated list of ingredients and a button that sends them to the Anthropic API and displays the response as a 5-day dinner menu. Use vanilla HTML, CSS, and JavaScript. No external libraries."
five rules that save the most time
1
Always paste your PRD at the start of a new session
AI coding assistants have no memory between sessions. Paste your PRD first. It takes ten seconds and saves twenty minutes.
2
One task per prompt
Build the form first. Then the button. Then the API call. Each step builds on the last.
3
When something is wrong, describe what you see
Not "fix the button." Say "the button is not responding when I click it. The console shows no errors. The function is defined but not being called."
4
Ask for explanations when you do not understand
Not because you need to understand every line, but because understanding what was built helps you prompt the next step correctly.
5
If the result is completely wrong, start a new session
Close the session, paste your PRD fresh, and start again with a better prompt. Almost always faster than continuing to iterate on something broken.
Your task this week SOP 02
Write your first real prompt for your landing page.

Using your PRD from SOP 01, write a prompt with all four parts: role, context, task, constraint. Read it back. Would someone with no context understand exactly what you want? Save it alongside your PRD.

When done A complete four-part prompt ready to paste into your AI coding assistant.
