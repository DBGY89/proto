Block 03 — When things go wrong 06

What to do when something breaks

Things break. This SOP gives you a process for when they do.

Things break. This SOP gives you a process for when they do.

Every builder breaks things. The ones who ship consistently are not the ones who break things less. They are the ones who know what to do when something breaks.

The process is always the same: read the error, understand what it is saying, find where it is coming from, fix the specific thing that is broken, verify the fix. In that order.

step one: open the browser console

Press F12 on Windows or Linux, or Command + Option + I on Mac. Click the "Console" tab. If there is an error, it will be there in red. Read the full message, not just the first line.

the most common errors
Very commonCannot read properties of undefined
Your code is trying to access something that does not exist yet. Usually because data has not loaded or a variable is empty. Check what the variable contains at the point of the error.
Very commonFailed to fetch / Network error
An API call failed. Check your environment variables first. Then the API key. Then the URL. CORS errors almost always mean you need to make the API call from a server function, not from the browser.
Very common404 Not Found
Something is looking for a file that does not exist at that URL. Check the path is spelled correctly. Case matters: Index.html and index.html are different files.
SometimesSyntaxError / Unexpected token
A mistake in the code syntax. A missing bracket, a comma in the wrong place. The error message tells you which line. Your AI assistant is very good at spotting these.
Sometimes401 Unauthorized / 403 Forbidden
An API is rejecting your request. Check your API key is correct and being sent. For Supabase, check your row level security policies allow the action.
how to ask your AI assistant for help
1
Copy the full error message from the console
Do not paraphrase. Copy the exact text. The specific wording often contains the answer.
2
Paste the relevant code alongside it
Include the function where the error is happening. Not the entire file. Just the relevant part.
3
Describe what you expected and what happened instead
"I expected the button to send the form data to the API. Instead I see this error and nothing happens." That sentence alone rules out half the possible causes.
4
If the fix does not work, start a new session
Close the session, paste your PRD and the relevant code fresh, and describe the problem again. Almost always faster than continuing to iterate.
Your task this week SOP 06
Break something in your project on purpose and fix it.

Open your index.html. Remove a closing tag, introduce a typo in a function name, or delete a semicolon. Save, refresh, open the console, read the error, fix it without asking the AI first. The goal is to feel what debugging feels like before you need it for real.

When done An error introduced and fixed. A first-hand understanding of what the browser console looks like when something goes wrong.
That is the bundle.

You now have everything you need to go from idea to a live product with users, data, payments, and AI. Solo. Go build something.
