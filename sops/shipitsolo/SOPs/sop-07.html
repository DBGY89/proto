Block 02 — Data 07

Supabase — store and read data

A real database for your project without building a backend. Free to start, and the free tier goes further than you think.

Is this SOP for you?

Use this SOP if your project needs to store data between visits. For a landing page, that means saving contact form messages. If your project only shows static information, skip this for now.

Without a database, data disappears the moment someone closes the browser. Supabase gives you a PostgreSQL database, an API to read and write data, and a dashboard — without writing a single line of backend code.

A few years ago, adding a database to a personal project meant setting up a server, configuring PostgreSQL, and writing an API from scratch. Supabase made that a 20-minute task.

A database is the right next step when your project needs to remember something between visits. If your contact form needs to save messages somewhere you can read them later, you need this.

When you have real users
1
Create a Supabase account and a new project
Go to supabase.com and sign up. Click "New project," give it a name, set a database password, choose a region. Takes about a minute to provision.
2
Create your messages table
Go to the Table Editor. Click "New table." Name it "messages." Add columns for name, email, and message. Supabase creates an ID and timestamps automatically.
3
Get your project URL and API key
Go to Settings, then API. Copy your Project URL and your public anon key. Never use the service role key in frontend code.
4
Ask your AI coding assistant to connect your project
Paste your PRD, your Supabase URL, and anon key. Ask it to add the Supabase JavaScript client and write code to insert form submissions into the messages table.
5
Set row level security policies
Go to Authentication, then Policies. Enable insert for anonymous users so your contact form can write data. Your AI assistant can write these policies if you describe the rules.

Move your keys to environment variables before deploying. SOP 08 explains exactly how.

Your task this week SOP 07
Save your contact form submissions to Supabase.

Create a Supabase project, add a messages table, connect your contact form. Test it by submitting the form and verifying the data appears in the Supabase dashboard. Move your API keys to environment variables before deploying.

When done A working contact form that saves submissions to a real database you can log into and read.
